## Deferred from: code review of 1-2-deterministic-core-skeleton (2026-10-28)

- **Back-to-back commands without an `advance` replay differently** (`src/core/run/replay.ts`). Replay runs one `advance(state, entry.atGameMs)` per entry; a zero-length advance can process another event due at that `gameMs` (for example a second `heavyDecisionDue`), which live play skipped. The contract is now in game-architecture.md D3. Decision for Story 1.6: enforce it in `app/session` (always advance before dispatch) or add a single core `step(state, atGameMs, command)` entry point.
- **Queue copied per event on the hot path** (`src/core/time/advance.ts:31` `slice(1)`, `src/core/time/scheduleEvent.ts:27` spread insert). Fine at today's queue sizes; violates the "no whole-collection copies per event" rule. Decision: accept with an explicit exception, or move to a head index / persistent structure when queues grow (Epic 2 messages).
- **`assertInvariant` in `shared/` with only `core/` consumers** (`src/shared/assertInvariant.ts`). Breaks the "used by at least two layers" admission rule until `platform/codec` (1.10) or `app` uses it. Decision for Tiziano: sign off, or move to a `core/invariants` module now.
- **Event id cap of 999,999 per run** (`ID_SEQUENCE_WIDTH = 6`, `src/core/constants.ts`). Every scheduled event spends a number; later stories add many kinds. Decide the width before Story 1.9 freezes the save format.
- **Commands and `RunStart` not decoded** (`src/core/run/applyCommand.ts`, `src/core/run/newRun.ts`). The log stores the command object by reference (extra fields included); live callers can pass invalid `speed`/`timing` values (caught only by `assertStateIsValid` after a replay); `loopNumber` has no range check. Owner: the save/import decoder (Stories 1.9/1.10).
- **`sha256Hex` and lone surrogates** (`src/shared/sha256.ts`). `TextEncoder` maps them to U+FFFD, so two different strings can hash alike. The fingerprint is safe (`canonicalize` escapes them through `JSON.stringify`). Story 1.10's export checksum must pass well-formed or escaped text.
- **Hot-path import ban is per file** (`eslint.config.js`). It covers `core/time/**` and `core/run/applyCommand.ts`, not helpers they may import later. Extend the file list when such a helper is added.
- **Rounding ban misses bitwise truncation** (`eslint.config.js`, raised in review run 2). `x | 0`, `~~x`, `x >>> 0` and `parseInt(String(x))` truncate toward zero and lint clean in `core/`; plain `a / b` is allowed too (`canonicalize` only catches the float at fingerprint time). A blanket ban breaks the legitimate int32 code (RNG derivation, SHA-256). Decision: keep it a review-checklist item, or write a typed rule that flags these on non-int32 operands.
- **Replay ignores the advance mode** (`src/core/run/replay.ts:14`, raised in review run 2). Replay always advances in `'present'`; the live mode is not in the input log. No handler reads `mode` yet. Story 1.6 (away/ending rules) must log mode changes as input or replay will diverge.
- **`GameState` holds current settings, not the start settings** (`src/core/run/gameState.ts`, raised in review run 3). `GameState extends RunStart`, but `applyCommand` overwrites `settings`, so after a setting change the state no longer carries the `RunStart` that `replay` needs, and `replay(state, state.inputLog)` still compiles (a `GameState` is assignable to `RunStart`) and throws "corrupt log". Decision for Story 1.9 (save record): store `RunStart` separately in the save, or keep `startSettings` in the state and stop `GameState` from extending `RunStart`.
